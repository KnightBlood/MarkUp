### 插件动态加载通道
- **宿主路径 API**：`host.app.getPath?('plugins' | 'pluginsLocal' | 'userData')`（可选方法，遵循 `print?` 模式）——`plugins` = **统一全局根 `~/.markup/plugins`（三壳完全一致）**：Electron IPC `markup:app:getPath`（`app.getPath('home')/.markup/plugins` + `mkdir`）、Tauri `get_path` command（`app.path().home_dir()/.markup/plugins` + `create_dir_all`）、Wails `HostService.GetPath`（`os.UserHomeDir()/.markup/plugins` + `MkdirAll`，未知名返回 null）；`pluginsLocal` = **程序目录旁 `plugins/`**（Electron `dirname(process.execPath)` / Tauri `current_exe().parent()` / Wails `filepath.Dir(os.Executable())`，解析为绝对路径返回、**不自动创建**，目录不存在时加载器跳过不报错）；`userData` = 配置根（不变）；web 无此方法 → 加载器静默 no-op
- **加载器**（`packages/ui/src/plugins.ts`，`renderShell` 尾部自动调用）：**先扫全局根再扫程序目录根**，合并扫描两根下 `<name>/manifest.json`（`{id,name,version,main?}`，缺字段/崩溃逐项记 `errors` 不中断；**同一 `id` 两根都存在时先扫的全局份赢、程序目录份跳过**；单根 readDir 失败只跳过该根）→ 读 `main`（默认 `index.js`）→ `new Function('api', '"use strict";' + code)` 执行（**受信本地插件，无沙箱、无 require/import，仅 `api` 在作用域**——README 已知问题）

## 已知问题 / 后续
1. **Electron**：`electron-builder` 在 pnpm workspace 下收集依赖时报 `No JSON content found`；本包无 runtime dependencies（仅 devDependencies），手工放置 app 目录可运行。若要正式 NSIS 安装包，需修 `electron-builder` 与 pnpm 10 兼容或改用 `files` + 关闭 node modules 收集。**主进程 workspace 导入坑（本轮修）**：`tsc` 对 `@markup/host-api` 的导入**原样保留**为 `require('@markup/host-api')`，而 `files: dist/**/*` 不打包 pnpm 的 node_modules（且该包 `main` 指向 TS 源码）→ 打包应用启动即 `Cannot find module '@markup/host-api'`（主进程弹 "A JavaScript error occurred in the main process" 后退出）。修法：`build:main` 追加 `node scripts/bundle-host-api.mjs`，用 esbuild 把该包打成 **CJS 单文件** 落到 `dist/main/node_modules/@markup/host-api/index.js`，靠 Node 向上查找命中（`scripts/_needles.ps1` 已加存在性断言）。
2. **Wails**：前端已 `go:embed` 进 exe（`go build` 前必须先 `frontend` 的 `vite build`，否则编译期报 embed 错误）。窗口必须用 `app.Window.NewWithOptions` 创建（裸 `application.NewWindow` 不会注册到 app，只出控制台无窗体）；且 `UseApplicationMenu: true`，否则 Windows/Linux 不显示应用菜单栏。服务绑定名必须用完整 FQN（见上），422 = 绑定名未命中（`transport_http.go` `httpError` 恒返回 422）。
3. **Tauri**：已用 `tauri build --no-bundle` 嵌入前端（修复 localhost 打不开问题）；未生成 installer/icon bundle（`targets: all` 需另跑 `tauri build`，本机无 admin 时可能受 NSIS 限制）。
4. **嵌入媒体导出**：model 导出页依赖 jsdelivr CDN script（离线打开无 3D 显示，video/mindmap 不受影响）；mindmap 导出为静态 SVG（编辑器内缩放/平移不保留）；打印/导出 PDF 时 `<video>`/`<model-viewer>` 属网页画布内容，可能呈黑块或静止帧（webview 打印对媒体/canvas 的限制，非本应用可控）。
5. **tsx 冒烟双模块实例**：tsx 按 import specifier 分模块实例（同一物理文件、不同相对路径会各评一次）——ui 测试与 shell/embedViewer 统一经 `packages/ui/src/ui/embeds.ts` 桥接 core embeds；后续给 core 加「模块级可变状态」的桥时，新增调用方务必走同一入口，勿从 `scripts/` 直连 `../../core/…`（会设到另一实例上、静默失效）。
6. **文档格式查看器**：vite 构建恒打一条无害警告——`Module "node:module" has been externalized`（embeds.ts 的 tsx/测试分支 `createRequire` 兜底，浏览器运行时永远走 `?url` asset 分支，externalized shim 不会被执行）；PlantUML 引擎为按需大 chunk（`plantuml-*.js` ≈3.5MB 懒加载 + `viz-global-*.js` ≈1.4MB script 资产，首屏不加载），仅在首个 plantuml 围栏水合时拉取；`renderToString` 共享引擎状态，多图经 `plantumlQueue` 串行 + 30s 超时，超大图或并发文档渲染会排队等待属预期行为；PlantUML 输出为引擎默认浅色主题（dark scheme 下对比度受限，后续可注入 `skinparams` 覆盖）。
7. **file-viewer（本轮）**：`@file-viewer/web-full` 包体量大（pnpm 存储 ~79MB），构建新增 `dist/file-viewer/` 资产目录（worker/WASM/字体/vendor，四壳各复制一份）；**dev 首次启动需把 ~3000 文件复制进 `public/file-viewer/`，本机（慢盘 + 杀软实时扫描）耗时数分钟**——vite 8 起该异步 `configureServer` 钩子会被 await、直接阻塞 `listen`（表现为启动"卡死"零输出），已用 `unblockDevAssetCopy()` 改为 fire-and-forget（web/tauri/wails 三处 `vite.config.ts`；electron dev 走 `vite build` 无 dev server 不受影响），服务先起来、资产边拷边由 `public/` 提供；拷贝完成前对尚未落盘的 viewer 资产请求仍会被 SPA fallback 吞成 HTML（刷新即恢复）；`public/vendor`、`public/wasm` 两个空目录壳被安全软件句柄锁死（ACL 读取即拒、内容已删空，无害，可随重建复删或忽略）；opt-in 系列（DICOM/签名/十六进制/BPMN/IFC）未装，对应扩展名经 file-viewer 路由会落到「不支持」而非自动下载；`.ppt`（二进制 PowerPoint 97-2003）经上游许可组件渲染**带水印且需 secure context**（http(s)/localhost，`file://` 下不可用）；导出 HTML 保留 file 源码块（Shadow DOM/Worker 不可序列化，`hydrateEmbeds` skip 通路）；viewer 内部错误仅体现为容器错误态、无独立日志通道（排查需开 devtools 看网络面板）；**拷贝截断坑（本轮实测）**：该插件 `closeBundle` 的资产拷贝会被外部因素（杀软/会话重启）静默中断——进程以 exit 1 退出且不打印任何错误，产物落在「部分完成」状态（实测 web/electron 一度只有 2082 个文件，缺 `vendor/pdf`（pdf.js fonts/cmaps 299）、`wasm`（42）与后半 `vendor/drawio`（516）；**完整 preset-all 资产应为 2957 文件**）。判定方法：比对 `dist/file-viewer` 文件数 / 存在 `vendor/pdf`、`wasm` 两个目录；补齐方法：从一次完整构建（如 tauri 前端 dist）`robocopy /E` 覆盖回去（`scripts/_needles.ps1` 已加这两条结构断言）。
8. **drawio/xmind 预览改由 file-viewer 承担（本轮）**：```drawio / ```xmind 走 `@file-viewer/renderer-drawing` / `renderer-mindmap`（均为离线内置引擎），因此**导出 HTML 不再内联它们的 SVG**——与 ```file 同路保留源码块（`hydrateEmbeds({ skip: ['file','drawio','xmind'] })`），目的是让渲染引擎单一化（自绘 mxgraph/markmap 曾分别崩在 `mxLoadResources is not defined` 与 markmap `renderData` 的 `undefined.map`）；**```plantuml 未切换**：file-viewer 的 PlantUML 为**服务端渲染**（`renderer-drawing` 的 `plantumlServerUrl`，未配置时只给 "Offline mode is active" 源码兜底），与全离线目标冲突，故仍用本地 `@plantuml/core` TeaVM 引擎（导出仍内联 SVG）。
9. **标签页与编辑历史**：切换/恢复标签会把适配器整体重建（`sync.setMarkdown`），ProseMirror 撤销栈**不跨标签保留**——`Ctrl+Z` 只回退当前标签内的编辑；同一标签内的撤销/重做正常。
10. **快捷键改绑不触及原生菜单**：设置 → 快捷键的改绑只作用于应用内 keymap（`CommandRegistry` overrides），Electron/Tauri/Wails 原生菜单项仍显示 `menu.json` 里的出厂加速器（两处显示可能不一致，功能以应用内为准）；应用内菜单栏（7 节）读的正是 registry，改绑实时一致。
11. **格式化选区吸附（实时预览）**：分屏/源码视图的选区是字符精确的；wysiwyg 的 markdown 偏移靠 `serializePrefix`（前缀序列化）反推，跨节点选区（围栏/表格/图片内部）会吸附到最近的合法文本位置——围栏代码块内的多行选区建议切到分屏/源码视图操作。空选区格式化会插入占位词（「粗体」等）并选中，输入即替换。块级格式（标题/引用/列表/任务/代码块）在实时预览走 ProseMirror 原生命令（撤销正常），在分屏/源码是「整行文本重写」（一次替换入撤销栈）。
12. **关闭窗口的未保存提示只在 web/Electron 生效**：web 走浏览器原生 `beforeunload` 框，Electron 走应用内对话框（`close-request` + `window.confirmClose`）；**Tauri/Wails 未实现这两个钩子**，关闭时直接退出、不拦截未保存改动（此前三壳都因 `beforeunload` 静默取消而「关不掉」，现至少保证能关）。后续给这两壳补 `confirmClose` + 关闭事件即自动复用渲染层同一套对话框。
13. **electron-builder 打包被中断后的锁残留**：强杀打包进程（或会话中断）会留下 `proper-lockfile` 锁，下次打包立刻失败于 `Lock file is already being held`——**重跑一次即可**（锁反映的是进程存活态，不是文件锁残留）；日志里的 `connect ETIMEDOUT …:443`（GitHub 不可达）**不影响 `--dir` 打包**：electron 发行包、`winCodeSign`（含 rcedit）、`nsis` 都在 `%LOCALAPPDATA%` 缓存里，实测离线也能打出完整 `win-unpacked`（含 exe 图标与 asar 完整性资源）。
